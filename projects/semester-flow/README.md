# Semester Flow｜个人学期工作流

基于 ChatGPT 与 Codex 构建的个人学期管理 Web 原型。

## 01 我为什么做它｜问题发现

我的课程、作业、志愿工作、个人项目和截止日期长期分散在不同平台。

普通日历可以记录固定时间，但很难处理：
- 未完成任务顺延
- 特殊教学周和假期
- 可以灵活安排的工作
- 每周目标
- 已完成任务回顾
- 学期中不断变化的计划

因此，我希望建立一个可以根据真实学期节奏持续调整的个人工作流。

## 02 产品目标｜我想解决什么

我最初希望把：

课程 + 每日任务 + 每周计划 + 弹性工作 + 提醒 + 总结

整合到一个网页中。

目标不是再做一个 Todo List，而是减少每天重复整理信息和重新规划的认知成本。

## 03 为什么使用 ChatGPT + Codex

### ChatGPT
主要用于：
- 把自然语言需求梳理成产品需求
- 讨论功能逻辑
- 拆解开发任务
- 分析实际使用后出现的问题

### Codex
主要用于：
- 建立 Web 原型
- 修改项目代码
- 实现功能
- Debug
- 根据反馈快速迭代

## 04 我和 AI 怎么分工

### 我负责
- 发现真实问题
- 定义使用场景
- 判断功能优先级
- 设计工作流
- 提供真实规则和例外情况
- 实际使用和测试
- 判断 AI 的实现是否真正解决问题
- 决定下一轮迭代

### AI 负责
- 需求结构化辅助
- 技术方案建议
- 原型代码生成
- 功能修改
- Bug 定位与调试

## 05 从第一版到迭代｜真正遇到的问题

第一版可以运行，但真正使用之后，我发现：

- 页面不会随日期自动跳转
- 每日目标和周计划存在交互重叠
- 很难提前添加未来日期的任务
- 每日总结使用成本过高，我实际更需要每周总结
- 每周任务只能看到标题，看不到具体内容
- 已完成任务不应该直接消失，而应该留下完成状态
- 电脑网页作为唯一入口不够灵活
- 我希望加入每周“在墨尔本/墨大想完成的一件事”

这些问题让我意识到：

**能运行的原型，不等于好用的产品。**

## 06 我学到了什么｜Reflection

这次 Vibe Coding 让我意识到，AI 大幅降低了把想法做成原型的技术门槛，但真正困难的部分仍然是：

**问题定义 → 情境理解 → 规则设计 → 产品判断 → 真实测试 → 迭代**

AI 很擅长回答“怎么实现”，但“为什么要做”“真正的问题是什么”“这个功能实际是否有用”，仍然需要人的判断。
