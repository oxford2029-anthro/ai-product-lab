Semester Flow｜个人学期工作流

基于 ChatGPT 与 Codex 构建的个人学期管理 Web 原型。

## 01 我为什么做它｜问题发现

我的课程、作业、志愿工作、个人项目和截止日期长期分散在不同平台。

普通日历可以记录固定时间，但很难处理：
- 未完成任务顺延
- 特殊教学周和假期
- 可以灵活安排的工作
- 每周目标
- 已完成任务回顾
- 学期中不断变化的计划

因此，我希望建立一个可以根据真实学期节奏持续调整的个人工作流。

## 02 产品目标｜我想解决什么

我最初希望把：

课程 + 每日任务 + 每周计划 + 弹性工作 + 提醒 + 总结

整合到一个网页中。

目标不是再做一个 Todo List，而是减少每天重复整理信息和重新规划的认知成本。

## 03 为什么使用 ChatGPT + Codex

### ChatGPT
主要用于：
- 把自然语言需求梳理成产品需求
- 讨论功能逻辑
- 拆解开发任务
- 分析实际使用后出现的问题

### Codex
主要用于：
- 建立 Web 原型
- 修改项目代码
- 实现功能
- Debug
- 根据反馈快速迭代

## 04 我和 AI 怎么分工

### 我负责
- 发现真实问题
- 定义使用场景
- 判断功能优先级
- 设计工作流
- 提供真实规则和例外情况
- 实际使用和测试
- 判断 AI 的实现是否真正解决问题
- 决定下一轮迭代

### AI 负责
- 需求结构化辅助
- 技术方案建议
- 原型代码生成
- 功能修改
- Bug 定位与调试

## 05 从原型到迭代｜真实使用后的变化

### V1｜先把我认为需要的功能都做进去

第一版的想法比较直接：我希望把 Daily Planning、Weekly Planning、课程、任务和总结尽可能整合到同一个系统里。

在设计阶段，这些功能看起来都很合理。

但真正连续使用后，我发现“功能存在”并不等于“我会使用”。

第一版暴露出几个明显问题：

- 每日总结操作成本太高，我经常不想填写
- 很难提前添加未来日期的任务
- 每周计划能够看到任务，但具体内容展示不够清楚
- 完成后的任务直接消失，不利于回顾这一周实际完成了什么
- 页面比较固定，无法很好适应临时变化
- 电脑网页作为主要入口，在临时调整计划时不够方便

### V2｜从“功能完整”转向“实际愿意使用”

第二轮迭代时，我没有继续增加功能，而是开始重新判断哪些功能真正有价值。

主要调整方向包括：

- 从每日总结转向更低频的每周复盘
- 保留已完成任务的状态，而不是直接删除
- 支持未来日期任务
- 提高周计划中任务内容的可见性
- 增加每周个人目标
- 提高整个工作流的灵活性

这次迭代让我开始关注的，不再只是“这个功能能不能实现”，而是：

**它是否真的降低了我的使用成本？**

## 06 我学到了什么｜Reflection

这次 Vibe Coding 让我意识到，AI 大幅降低了把想法做成原型的技术门槛，但真正困难的部分仍然是：

**问题定义 → 情境理解 → 规则设计 → 产品判断 → 真实测试 → 迭代**

AI 很擅长回答“怎么实现”，但“为什么要做”“真正的问题是什么”“这个功能实际是否有用”，仍然需要人的判断。

## 07 当前状态

目前项目仍在真实使用和持续迭代中。

下一阶段重点：
- 优化移动端或更方便的访问方式
- 完善未来任务添加
- 改进任务完成状态
- 从每日总结调整为每周复盘
- 根据实际使用继续删减不必要的功能力
