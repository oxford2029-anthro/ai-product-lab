# Semester Flow Build Log

## 2026-08-03｜第一次原型

### 今日目标

把个人学期课程、待办、每日提醒和总结需求转化为一个可以运行的 Web 工作流。

### 我提供给 AI 的信息

- 本学期课程时间
- 特殊 Lecture 的出现周次
- 需要排除的旧课程
- 每天 8:30 的计划提醒
- 每天 22:00 的总结安排
- MAL 工作需要弹性分配
- Apple Calendar 主要负责提醒

### GPT 完成的工作

- 梳理零散需求
- 识别课程、任务和提醒之间的区别
- 设计 Today、Week、Tasks 和 Reflection 页面
- 提出数据结构和开发步骤

### Codex 完成的工作

- 创建 React / Vite / TypeScript 项目
- 搭建页面结构
- 编写课程和任务逻辑
- 实现本地数据保存
- 调整界面和功能错误

### 我完成的工作

- 判断需求是否准确
- 补充遗漏的课程例外
- 删除不属于本学期的课程
- 决定网页和 Apple Calendar 的功能边界
- 检查页面是否符合真实使用习惯
- 对生成结果提出修改要求

### 遇到的问题

- AI 容易把所有日程视为固定事件
- 特殊教学周需要单独定义
- 课程数据存在历史信息混入的问题
- “提醒”和“任务管理”需要分开设计
- 页面能够运行不等于工作流真正可用

### 今日结论

AI 可以快速把需求转化为原型，但前提是用户能够持续澄清情境、规则和例外。

对于个人工作流产品，需求中的例外情况往往比一般功能更重要。

### 下一步

- 连续真实使用一周
- 记录哪些功能被实际使用
- 测试任务顺延
- 优化最重要事项的视觉区分
- 保存关键开发提示词和修改记录
